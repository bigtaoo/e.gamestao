# Pata（仿版）· 云养宠 + 房间装扮

参照 Pata（重庆皮皮喵科技的「亲友闺蜜一起玩的小世界」）做的 Web 版切片。
**PixiJS v8 + TypeScript + Vite**，没有任何美术资源——宠物、家具、图标全部程序化绘制。

```bash
npm install
npm run dev        # 客户端 http://localhost:5180
npm run server     # 好友服务 http://localhost:5183（零依赖，可选）
npm run build      # tsc --noEmit + vite build
```

竖屏设计（基准 430×932），桌面端居中显示成手机外框，移动端铺满。

---

## 界面结构

**房间就是主界面**，宠物在等距房间里散步，所有日常互动都发生在这。
底部导航固定 5 个：`房间 | 任务 | 好友 | 装扮 | 商店`；
装修和日记这类次要入口走右侧竖排，不占导航位。

## 已实现

| 模块 | 内容 |
|---|---|
| **云养宠** | 饱食/清洁/精力/心情四维状态，喂食·洗澡·摸摸·玩耍四种互动（带冷却），点宠物即摸摸，亲密度升级，表情随状态变化，气泡台词 |
| **房间装扮** | 8×8 等距网格，64 件家具 ×9 套主题，**按住直接拖、松手落位**，旋转 / 收纳 / 一键清空（两段确认），6 地板 + 6 墙纸，舒适度与齐套加成 |
| **任务** | 8 个每日任务（喂食/洗澡/陪玩/摸摸/日记/摆家具/串门/帮喂饭）+ 5 个终身成就，按自然日重置，一键领取，导航红点提示 |
| **好友** | 好友码互加、串门看对方房间（复用等距渲染加载快照）、帮喂饭，离线时优雅降级 |
| **捏人** | 8 体色 / 5 花纹 / 6 眼型 / 6 腮红 / 6 头饰；用立绘贴图时自动只留可生效的项 |
| **日记** | 5 种心情标签 + 文本，写一篇给 20 金币 |
| **经济** | 金币（挂机产出 + 每日照料 + 任务 + 日记）、♥ 爱心（升级与成就） |
| **离线演算** | 纯 UTC 时间戳差值驱动，回来时结算并弹报告，离线收益封顶 8 小时 |
| **存档** | localStorage，带 `schemaVersion` 与字段补齐迁移，节流写入 + `pagehide`/`visibilitychange` 强制落盘 |

## 关键设计决策

**装饰和养成必须互为供需，否则装修没有动力。**（这条沿用了 `game/游戏设计方案.md` 里的结论）
具体接法是：房间舒适度 → 决定**心情上限** → 心情决定**金币产出速率** → 金币买家具。
所以「房间空荡荡」会直接卡住心情天花板，玩家能立刻感知到装修的收益。

```
照顾(饱食·清洁) ─┐
                  ├→ 心情 ──→ 金币/小时 ──→ 买家具 ──→ 舒适度 ─┐
房间舒适度 ───────┘                                              │
       ↑                                                         │
       └─────────────────────────────────────────────────────────┘
```

其它几条：

- **不做体力系统**，节奏由互动冷却和状态衰减自然限制。
- **不做负反馈**（不会生病、不会跑掉），符合「社恐友好、低压力」的产品定位。
- 时间只信 `UTC 时间戳 + 配置时长`，客户端每帧只做插值显示。前台演算每 250ms 跑一次，走的是和离线结算**完全同一条代码路径**（`systems/sim.ts` 的 `advance`）。
- 金币结算保留小数余量（`coinFrac`），否则前台的高频小步长会被 `Math.floor` 全部抹成 0。

## 宠物形象：矢量 / 贴图双轨

默认走**程序化矢量绘制**（`src/render/pata.ts`）：垂耳兔，身体是 `FillGradient` 上白下黄的渐变，
拆成 身体 / 左耳 / 右耳 / 前景(爪子·绒毛) / 脸 / 头饰 六层，只在配置变化时重绘，逐帧只改变换——
所以耳朵能跟身体错开相位单独摆动，眨眼和表情也能实时切。

如果需要**和参考图完全一致**的立绘，把图片存成 `src/assets/placeholder/pata.png` 即可，
启动时自动检测并切换到贴图模式，不用改代码。目录为空就回落到矢量版。

两种模式的取舍：

| | 矢量 | 贴图 |
|---|---|---|
| 和参考图的相似度 | 神似 | 完全一致 |
| 体色 | 8 种渐变 | 靠 `tint` 染色，近似 |
| 花纹 / 眼型 / 腮红 | 可换 | 画死在图里（面板会自动隐藏这三项） |
| 头饰 | 矢量叠加 | 矢量叠加（图里已有光环的话选「不戴」） |
| 动画 | 呼吸 + 眨眼 + 耳朵摆动 + 表情 | 只有整体挤压拉伸 |

⚠️ `src/assets/placeholder/` 已加进 `.gitignore`。那里现在放的是网上找的参考图，
只用于本地预览，**不要提交、不要随构建发布**，上线前必须换成原创或已授权的美术。

## 调试控制台

浏览器打开 `http://localhost:5180/?dev`，控制台里：

```js
pata.coins(999999)     pata.level(99)      pata.hearts(999)
pata.unlockAll()       // 解锁所有家具/地板/墙纸/装扮
pata.fill()            // 四维状态拉满
pata.state             // 直接看存档
pata.room              // 场景对象，查层级/命中判定用
pata.reset()           // 清档重来
```

只在 URL 带 `?dev` 时挂载，正常进游戏碰不到。

之所以要专门做这个入口：**直接改 localStorage 没用**——退出时 store 会把内存里的状态原样
写回去，把手改的值盖掉。要生效必须改内存里的 state 再走正常存档流程。


## 好友服务（`server/`）

零依赖，只用 node 内置模块，JSON 文件存储：

```bash
npm run server              # 5183 端口，数据落在 server/data.json
PORT=8080 npm run server
```

**存档仍以客户端 localStorage 为准**，服务端只存一份「房间快照」（昵称/等级/形象/房间布局）
供好友查看。异步社交不需要实时状态同步，把整个存档搬上服务端会立刻引出
冲突合并、防作弊、账号找回一整套问题，对这个阶段不划算。

| 接口 | 作用 |
|---|---|
| `POST /api/register` | 注册，返回 userId + token + 好友码 |
| `GET/PUT /api/me` | 拉取资料与待结算的帮忙记录 / 上传房间快照 |
| `GET/POST /api/friends` | 好友列表 / 用好友码互加 |
| `GET /api/visit?id=` | 串门，取对方房间快照 |
| `POST /api/help` | 帮邻居喂饭，写进对方 inbox 待结算 |

⚠️ **目前没有正经鉴权**：token 明文存在 localStorage，拿到就能改快照。原型够用，上线前必须换成真正的账号体系。

## 代码结构

```
src/
  core/util.ts          纯函数：clamp/lerp/时间格式化/颜色明暗
  model/
    types.ts            GameState 及各子状态
    store.ts            存档读写、迁移、订阅、节流落盘
  systems/
    sim.ts              状态衰减、舒适度、等级、离线结算  ← 数值核心
    actions.ts          喂食/洗澡/摸摸/玩耍/购买/背包
  data/                 配置表：avatar / food / furniture
  render/
    pata.ts             程序化宠物（分身体/脸/头饰三层 Graphics，逐帧只改变换）
    homeScene.ts        主场景特写，墙纸地板与房间联动
    roomScene.ts        等距房间、放置校验、宠物散步
    furniture.ts        等距绘制例程 + SVG 缩略图
  ui/                   DOM 层：弹层、商店、捏人、日记、外壳
  app.ts                场景切换、HUD、导航、编辑条、弹窗
```

分层规则：`View 只读 Model、只发命令；Systems 改 Model；存档只序列化 Model`。
`systems/` 和 `model/` 没有任何 `pixi.js` 依赖，可以直接单测。

渲染上有意分成两层：**Pixi 画世界**（宠物、房间），**DOM 画界面**（列表、表单、弹层）。
中文排版、滚动列表、输入框交给浏览器做，比在 Canvas 里重造一套省太多。

## 没做的部分

对齐原版还差这些，按建议优先级排：

1. **正经账号体系** —— 现在只有匿名 token，换设备就丢号，也没有任何防篡改。
2. **派对小游戏** —— 谁是卧底 / 你画我猜。要实时房间服 +（理想情况）语音，是整个产品里成本最高的一块，建议单独立项。
3. **墙面挂件** —— 挂画、窗户、时钟。需要一套独立于地面网格的墙面放置模式，所以这轮没做。
4. **加工链** —— 原料→半成品→家具，用来吸收过剩金币、拉长经济纵深。
5. **存档上云** —— 目前存档只在 localStorage，清缓存即丢。`model/store.ts` 的读写已收口在一处，换成 REST 只改那一个文件。
