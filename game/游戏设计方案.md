# 农场 · 家园 手游设计方案 v0.1

> 依据 `game/1789113736960_IMG_3432 (1).HEIC` 手绘原型整理。工程：`meng/`（Unity 6000.3.9f1，URP，当前为 Netcode for GameObjects 多人示例模板）。

## 1. 原型解读

逐格放大后，六屏内容如下：

| 位置 | 画面 | 草图里看到的元素 |

**结论**：这是一个"农场经营 + 家园装饰 + 轻社交"的休闲手游，竖屏，单人异步玩法为主。

---

## 2. 定位

- **品类**：休闲模拟经营（Farm + Home Decor），单机式体验 + 异步社交。
- **参考**：《梦幻花园/家园》的装饰驱动、《开心农场》的作物计时、《星露谷》的收集感（不要它的实时操作强度）。
- **用户**：25–45 岁泛用户，碎片时间 3–8 分钟/次，一天 3–5 次。
- **设备**：手机竖屏 1080×1920 基准，适配 18:9 ~ 20:9；目标中低端机 60fps。
- **一句话**：种地养鸡攒钱，把家一点点装成自己的样子，顺手去邻居家浇个水。

---

## 3. 核心循环（最关键的设计决策）

```
播种/喂养 → 等待成熟 → 收获 → 金币·材料 → 买家具/开新地块 → 舒适度提升 → 产出加成 ↺
                                          ↘ 好友互访帮浇水 → 友情点 → 限定装饰 ↗
```

**必须把"装饰"和"经营"打通，否则装饰会变成没有目的的消耗品。**推荐机制：

- 房间内每件家具有 `舒适度` 分值；同套装齐套额外 +20%。
- 房间总舒适度 → 分档解锁全局加成：作物售价 +x%、成熟时间 -y%、离线上限时长 +z 小时。
- 反过来，高级家具需要农场产出的**加工材料**（棉花→布料→沙发），让农场成为装饰的唯一来源。

这样两个系统互为供需，玩家不会在"我为什么要装修"上流失。

## 4. 系统设计

### 4.1 种植

- 地块网格 `4×3` 起步，最多扩到 `8×6`；扩地消耗金币 + 等级门槛（价格指数增长）。
- 状态机：`空地 → 已播种 → 生长(n阶段) → 成熟 → 枯萎(可选)`。生长只用 **时间戳差值** 计算，不跑 Update。
- 交互：单指点击播种/收获；长按拖动 = 批量刷过多个地块（休闲游戏的关键手感）。
- 加速：浇水（-10% 剩余时间，每块每周期 1 次）、肥料（道具）、好友帮浇水。
- 建议**不做病虫害/枯萎惩罚**（负反馈会赶走休闲用户），最多做"成熟后品质随时间缓慢下降"的软提示。

示例数值（首版配表）：

| 作物 | 解锁等级 | 种子 | 时长 | 售价 | 经验 |
|---|---|---|---|---|---|
| 萝卜 | 1 | 10 | 5 min | 25 | 3 |
| 白菜 | 2 | 20 | 15 min | 55 | 6 |
| 玉米 | 4 | 45 | 1 h | 130 | 15 |
| 草莓 | 7 | 120 | 4 h | 380 | 40 |
| 南瓜 | 11 | 300 | 8 h | 900 | 90 |

原则：时长档位覆盖"上厕所 / 午休 / 下班 / 过夜"四段；长周期作物单位时间收益略高（约 1.3–1.5×）但吃解锁等级。

### 4.2 养殖

- 畜栏是一个"建筑"：`鸡舍 → 牛棚 → 羊圈`，等级决定容量。
- 循环：投喂饲料（由玉米/小麦加工）→ 计时 → 产出（蛋/奶/毛）→ 出售或进加工链。
- 亲密度：连续按时投喂提升，满级产出概率掉落稀有材料。这是唯一鼓励"按时回来"的钩子，别再加第二个。

### 4.3 加工链（第二阶段再上）

`小麦 → 面粉 → 面包`、`棉花 → 布 → 沙发`。加工台有队列和槽位，槽位用硬通货或任务解锁。作用：吸收过剩原料、拉长经济纵深。

### 4.4 房间装饰

- 视角：2.5D 等距（与左上/左下草图一致），房间逻辑网格 `10×10`，家具用 `footprint(w,h)` 占位 + 四向旋转。
- 分层：地板 / 墙面 / 地面家具 / 桌面小物 / 墙挂 / 地毯（可被家具覆盖）。至少要做"地毯层"和"桌面层"，否则摆出来很穷。
- 编辑模式：进入后底部弹出家具背包（草图左上那排横栏），拖拽放置，非法位置红色高亮；支持撤销、一键收纳、随机换色。
- 家具变体：同一模型 × 5 套配色 = 5 件商品。**这是控制美术成本的最重要手段。**
- 主题套装：田园 / 北欧 / 和风 / 节日限定；齐套给舒适度加成和成就。

### 4.5 商店（中下屏）

分页：种子 | 家具 | 道具 | 限时。每格显示图标、价格、解锁等级。限时页做每日刷新 6 件 + 一件折扣，制造每日打开的理由。

### 4.6 社交

- 好友列表（中上屏）：头像、昵称、等级、在线/最近活跃、一键访问、赠送体力外的"小礼物"。
- 好友家园（右上屏）：只读快照 + 有限交互：
  - 帮浇水 / 帮喂食：双方各得友情点，每日每人上限 5 次、全局 20 次。
  - 点赞房间 → 装饰榜单（给装饰玩家提供展示出口，这是装饰玩法的动力来源之一）。
  - **不建议做"偷菜"**：正向互助的留存效果不差，但负面情绪和客诉成本高。如果一定要做，改成"拾取掉落"：好友地里随机生成可拾取的小掉落物，不减少主人收益。
- 友情点商店：限定家具、稀有种子。

### 4.7 经济与养成

- 双货币：金币（软，产出）+ 星钻（硬，付费/少量任务给）。
- **不做体力系统**。节奏由"地块数量 × 作物时长"自然限制，体验更友好。
- 等级：经验来自收获、完成订单、装饰。每级解锁作物/家具/地块，等级曲线前 10 级快（第一天能到 6–8 级）。
- 订单板：3 个常驻订单（交付指定作物 → 金币 + 经验），2 小时刷新一个。这是消耗背包、引导种植结构的核心调节阀。
- 图鉴/成就：作物图鉴、家具图鉴、套装收集，给长期目标。

## 5. 首日体验（FTUE）

前 5 分钟必须走完一次完整循环，且要让玩家**在第 3 分钟就摆下第一件家具**：

1. 登录（游客一键进入，账号绑定延后到第 2 天再提示）。
2. 镜头俯冲到农场，指引种 2 块萝卜（5 分钟→首次强制改成 20 秒）。
3. 收获 → 得金币 → 商店买一张椅子。
4. 切到房间，摆椅子，舒适度 +，弹出"舒适度提升 → 作物售价 +2%"的因果提示。
5. 领新手礼包 → 解锁鸡舍 → 引导加好友。

## 6. UI 与信息架构

```
Boot ─ Login（游客/账号）
        └─ Home 场景（单场景，相机切换）
             ├─ 农场视图（大厅/默认）
             │    ├─ 顶部 HUD：头像·等级·金币·星钻·+ 按钮
             │    ├─ 右侧：任务/订单、邮件、活动
             │    └─ 底部导航：农场 | 房间 | 商店 | 好友 | 背包
             ├─ 房间视图（装饰编辑模式）
             ├─ 商店（全屏弹层）
             ├─ 好友列表（全屏弹层）
             └─ 好友家园（独立加载，只读快照）
```

- 底部导航固定 5 个，不超过 5 个。草图里左侧的竖排按钮留给"次要功能"（设置、排行、签到），避免和底部导航打架。
- 所有弹层用统一的 `PopupManager`（栈式，ESC/返回键逐层关闭）。
- 建议 UI 用 **UI Toolkit**（工程里 Blocks 模块已经有 PanelSettings 和 USS 的用法），列表型界面（好友、商店、背包）用虚拟列表，性能和迭代速度都更好；场景内的世界空间 UI（作物气泡、按钮）用 uGUI/TMP 更方便。

## 7. 技术方案

### 7.1 关于现有工程

`meng/` 目前是 Unity 的多人示例模板（`Blocks.*`、`Platformer`、`Shooter` 程序集，NGO + Multiplayer Services）。**农场社交是异步社交，不需要实时状态同步**，建议：

- 保留 `Assets/Core`（Art/Audio/Data/Settings 结构可复用），移除 `Platformer`、`Shooter`、`Blocks.*` 示例及对应 `.csproj`/程序集定义，卸载 `netcode.gameobjects`、`transport`、`multiplayer.tools`、`multiplayer.playmode`、`animation.rigging`、`vehicles/cloth/terrain` 等用不到的模块——包体和编译时间都会明显下降。
- 好友访问用**数据快照**：服务端存一份玩家家园的序列化布局，访问时下载 JSON 重建场景，不需要连线。

### 7.2 分层架构

```
Model（纯 C#，无 UnityEngine 依赖，可单测）
  PlayerState / FarmState / RoomState / Inventory / Wallet
Systems（无状态逻辑）
  FarmSystem  DecorSystem  EconomySystem  QuestSystem  SocialSystem
Services（可替换接口）
  ITimeService  IStorage(Local/Remote)  IConfigProvider  IAnalytics
View（Unity 层）
  FarmView  RoomView  UI（UI Toolkit 面板 + ViewModel 绑定）
```

规则：View 只读 Model、只发命令；Systems 改 Model 并抛事件（复用 `Assets/Core/GameEvents`）；存档只序列化 Model。

### 7.3 时间与防作弊

- 所有生长/产出只依赖 `UTC 时间戳 + 配置时长`，客户端每帧只做插值显示。
- `ITimeService` 以**服务器时间**为准（登录时同步 offset），本地时间跳变时取"上次已知服务器时间"的单调值，杜绝改系统时间加速。
- 结算在服务端复算（有后端后）；纯本地版先做 HMAC 签名存档，防止手改 JSON。

### 7.4 存档

单文档 JSON，带 `schemaVersion` 与迁移器链：

```json
{
  "schemaVersion": 3,
  "playerId": "u_1001",
  "level": 7, "exp": 1240,
  "wallet": { "coin": 5230, "gem": 42, "friendPoint": 118 },
  "farm": {
    "plots": [
      { "id": 0, "cropId": "corn", "plantedAt": 1757500000, "watered": true },
      { "id": 1, "cropId": null }
    ],
    "barns": [ { "id": "coop", "level": 2, "fedAt": 1757498000, "intimacy": 34 } ]
  },
  "room": {
    "floorId": "wood_02", "wallId": "cream_01",
    "items": [ { "defId": "sofa_green", "x": 3, "y": 5, "rot": 1, "layer": 2 } ],
    "comfort": 860
  },
  "inventory": [ { "id": "corn", "n": 12 } ],
  "quests": { "daily": [ ... ], "orders": [ ... ] }
}
```

- 写入节流（5 秒合批）+ 双缓冲文件（`save.json` / `save.bak`），`OnApplicationPause` 强制落盘。
- 远端：先 `IStorage` 本地实现，后接 Unity Cloud Save 或自建 REST，接口不变。

### 7.5 配置表

CSV/Google Sheet → 导入生成 ScriptableObject（`CropDef`、`FurnitureDef`、`AnimalDef`、`QuestDef`、`LevelCurve`），运行时只读、可热更（Addressables 预留）。**第一天就把配表管线搭好**，数值同学能独立迭代是这类游戏的生命线。

### 7.6 放置系统（房间/农场共用）

- 逻辑层：`GridMap`（`bool[,] occupied` + `Dictionary<Vector2Int, PlacedItem>`），放置校验 = footprint 位运算，O(w·h)。
- 表现层：等距坐标 `screen = (x - y) * tileW/2, (x + y) * tileH/2`，排序用 `x + y + layer` 算 `sortingOrder`。
- 拖拽：屏幕坐标 → 网格坐标取整，吸附 + 半透明预览 + 非法红色。
- 撤销栈只记录 `(itemId, from, to, rot)`，实现廉价。

## 8. 美术方向

- 2.5D 等距，手绘卡通，暖色调（米黄/草绿/奶油）；描边 + 平涂，降低建模/打光成本。
- 素材规范：tile 128×64；家具以 tile 倍数出图，统一锚点在底面中心；Sprite Atlas 按"房间/农场/UI/角色"分包。
- 家具复用策略：`基础模型 × 配色变体 × 材质变体`，1 套模型出 4–6 件商品。
- 首版内容量估算：作物 12、动物 3、家具 60（≈15 个基础模型）、地板墙纸各 8、UI 图标 80。

## 9. 变现与留存（首版只做埋点，不急着上）

- 星钻直购、成长基金、月卡（每日金币 + 一件专属家具）。
- 限定套装礼包（装饰玩家付费意愿最高的点）。
- 激励视频：翻倍收获、加速一次、商店刷新。
- 留存钩子：每日签到、订单板、亲密度投喂、好友互助上限、周末装饰主题活动。
- 必须埋的指标：FTUE 各步流失、次留/7 留、首次装饰时间、地块扩张曲线、金币产出/消耗比、装饰编辑时长。

## 10. 里程碑（单人全职约 9–10 周出可玩 MVP）

| 阶段 | 周期 | 交付 |
|---|---|---|
| M0 框架 | 1 周 | 工程瘦身、分层骨架、配表管线、存档、时间服务、Boot→Login→Home |
| M1 种植闭环 | 2 周 | 地块、播种/浇水/收获、背包、金币、商店买卖 |
| M2 养殖 + 加工 | 1.5 周 | 鸡舍、投喂产出、简单加工台 |
| M3 房间装饰 | 2 周 | 等距网格、拖拽放置/旋转/收纳、家具背包、舒适度与加成 |
| M4 社交 | 1.5 周 | 好友列表、家园快照、帮浇水、友情点商店 |
| M5 打磨 | 1 周 | FTUE、订单板、图鉴、音效、性能与适配 |

**垂直切片优先**：M1 结束时就应该是一个能连续玩 10 分钟的完整小游戏，而不是一堆半成品系统。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 装饰与经营脱节，装修没动力 | 舒适度直接给经济加成 + 高级家具吃农场材料 + 好友点赞榜 |
| 家具内容量是无底洞 | 模型×配色变体；套装化排期；先 60 件够用 |
| 离线收益被刷 | 服务器时间戳 + 服务端复算 + 存档签名 |
| 好友系统需要后端 | 先做"离线快照 + 假好友（NPC 邻居）"版本，后端就绪后无缝替换 `SocialService` |
| 沿用多人模板导致复杂度失控 | M0 就砍掉 NGO 相关模块，别让实时同步进入架构 |
| 等距放置的排序/穿插 bug | 逻辑网格与渲染解耦，`sortingOrder = (x+y)*10+layer`，早写单测 |
